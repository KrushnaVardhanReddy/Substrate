TASK: P1e-T02 — Apache Avro Schema Registry Compatibility Adapter

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add Apache Avro breaking-change detection to the Substrate diff engine by
delegating compatibility checks to the Confluent/Apicurio Schema Registry REST
API. This is NOT a custom Avro parser — Substrate wraps the registry response
into a DiffReport. No subprocess, no new CLI tool, pure net/http.

3. FILE: engine/internal/diff/avro.go  (CREATE NEW)

   Package: package diff

   ONLY use Go stdlib: net/http, encoding/json, fmt, io, time, strings
   NO external dependencies.

   Internal struct:
   type schemaRegistryCompatResponse struct {
       IsCompatible bool     `json:"is_compatible"`
       Messages     []string `json:"messages"`
   }

   Implement this function:

   func CompareAvro(baseFile, headFile string, cfg *config.SubstrateConfig) (*report.DiffReport, error)

   FULL implementation flow:

   Step 1: Check cfg.Avro == nil OR cfg.Avro.SchemaRegistryURL == ""
     → Return DiffReport with 1 WARNING change:
       RuleID: "AVRO_NO_REGISTRY_CONFIGURED"
       Severity: WARNING
       Description: "Avro compatibility checking requires schema_registry_url in substrate.yaml under the avro: block"
       Recommendation: "Add avro:\\n  schema_registry_url: https://your-registry.com\\n  subject: your-topic-value"

   Step 2: Read headFile content (raw bytes — .avsc is JSON)
     → On read error: return error

   Step 3: Determine subject name
     → Use cfg.Avro.Subject if non-empty
     → Else derive: cfg.Service + "-value"
     → If cfg.Service is also empty: use "unknown-value"

   Step 4: Build Schema Registry API request
     URL: cfg.Avro.SchemaRegistryURL + "/compatibility/subjects/" + subject + "/versions/latest"
     Method: POST
     Headers:
       Content-Type: application/vnd.schemaregistry.v1+json
       Accept: application/vnd.schemaregistry.v1+json
     Body: {"schema": "<JSON-escaped content of headFile>"}
     Timeout: 10 * time.Second

     If cfg.Avro.Username != "":
       req.SetBasicAuth(cfg.Avro.Username, cfg.Avro.Password)

   Step 5: Execute HTTP request
     On network error (timeout, connection refused, etc.):
       Return DiffReport with 1 WARNING:
         RuleID: "AVRO_REGISTRY_UNAVAILABLE"
         Description: "Could not reach Schema Registry: " + err.Error()
         Recommendation: "Check that schema_registry_url is correct and the registry is reachable from CI."

   Step 6: Read + parse response body
     On non-2xx status (e.g. 404, 500):
       Return DiffReport with 1 WARNING:
         RuleID: "AVRO_REGISTRY_UNAVAILABLE"
         Description: "Schema Registry returned HTTP " + statusCode

   Step 7: Check is_compatible
     → true: Return DiffReport with 0 changes (SchemaType: "avro", all slices empty)
     → false: Return DiffReport with 1 BREAKING change:
         RuleID: "AVRO_INCOMPATIBLE"
         Severity: BREAKING
         Path: subject
         Description: strings.Join(response.Messages, "; ")
           (or "Schema Registry reported incompatibility" if messages is empty)
         Recommendation: "Review Avro schema evolution rules. Adding a field without a default value is backward-incompatible."

   DiffReport construction:
   Always set SchemaType: "avro" and ComparedAt: time.Now().UTC().Format(time.RFC3339).

4. FILE: engine/internal/diff/avro_test.go  (CREATE NEW)

   Package: package diff_test

   Use httptest.NewServer() to mock the Schema Registry. NO real network calls.

   5 mandatory test cases:

   1. "no registry URL configured"
      cfg.Avro == nil (or cfg = &config.SubstrateConfig{})
      Expected: 0 BREAKING, 1 WARNING with RuleID "AVRO_NO_REGISTRY_CONFIGURED"

   2. "registry returns compatible"
      Mock server: 200, body: {"is_compatible": true}
      Expected: 0 BREAKING, 0 WARNING, SchemaType == "avro"

   3. "registry returns incompatible"
      Mock server: 200, body: {"is_compatible": false, "messages": ["removed field 'id'"]}
      Expected: 1 BREAKING with RuleID "AVRO_INCOMPATIBLE", description contains "removed field"

   4. "registry returns HTTP 500"
      Mock server: 500, body: {"error": "internal server error"}
      Expected: 0 BREAKING, 1 WARNING with RuleID "AVRO_REGISTRY_UNAVAILABLE"

   5. "registry connection refused"
      Use a URL that is guaranteed to fail (e.g. http://127.0.0.1:1 — port 1 is always closed)
      Expected: 0 BREAKING, 1 WARNING with RuleID "AVRO_REGISTRY_UNAVAILABLE"

   Test helper: create a minimal .avsc file in t.TempDir() for headFile input.
   Sample content: {"type": "record", "name": "Payment", "fields": [{"name": "id", "type": "string"}]}
