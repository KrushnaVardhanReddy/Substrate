CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Do NOT use third-party chat widget libraries (e.g., intercom, drift). Build a native Svelte 5 component.
- You MUST use Svelte 5 Runes (`$state()`, `$derived()`) for managing the chat history state. DO NOT use Svelte 4 `let` reactivity for complex objects.
- Ensure the widget uses the exact dark mode aesthetics and tokens from the Phase 11 Premium Aesthetics System (`bg-[var(--bg-card)]`, glassmorphism, etc.).

CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
The Svelte frontend lives in `dashboard/`.
Components are in `dashboard/src/lib/components/`.
The global layout is in `dashboard/src/routes/(app)/+layout.svelte`.
The AI endpoint is `POST /api/v1/ai/analyze`.

⚠️ CRITICAL CONTEXT: EVENT BUBBLING & CLICK OUTSIDE ⚠️
When building the floating widget, clicking outside the chat window should close it. Ensure you implement a robust `use:clickOutside` action or window event listener that does not conflict with the Svelte Flow canvas interactions. Svelte Flow actively manages pointer events, so the Copilot widget must have a higher `z-index` and properly call `stopPropagation` when clicking inside the chat to prevent the canvas from panning.
