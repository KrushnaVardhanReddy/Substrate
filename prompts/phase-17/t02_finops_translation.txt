TASK: P17-T02 — Legacy API FinOps Translation

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Expand the existing "Zombie API" detection system to calculate and display the estimated dollar amount saved by sunsetting legacy endpoints. By assigning a financial value to unused API endpoints, Engineering Managers can justify prioritization of API deprecations.

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
1. Do not use mocks in backend tests.
2. The UI must use Svelte 5 Runes ($state, $effect, etc).
3. Svelte 5 UI Constraints: Substrate uses Svelte 5 runes mode. Due to prop restrictions, NEVER use barrel imports for `lucide-svelte` icons (e.g., `import { Activity } from 'lucide-svelte'`). You MUST use direct imports (e.g., `import DollarSign from 'lucide-svelte/icons/dollar-sign'`) to avoid `Cannot use $$props in runes mode` errors.
4. Calculate savings using $500/month per zombie endpoint.

═══════════════════════════════════════════════════════════════
CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
- The zombie endpoints API is `GET /api/v1/org/{org}/zombies` implemented in `api/internal/handlers/otel_webhook.go`.
- It currently returns a JSON array of `sqlcgen.ZeroTrafficEndpoint`.
- The dashboard zombie UI is at `dashboard/src/routes/(app)/org/[org]/zombies/+page.svelte`.
