═══════════════════════════════════════════════════════════════
CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
The main API entrypoint is likely `api/cmd/server/main.go`.
HTTP routes are currently registered in `api/internal/server/`.
We need a parallel MCP routing layer in `api/internal/mcp/`.

⚠️ CRITICAL CONTEXT: HEADLESS MODE ⚠️
When the `--headless-mcp` flag is passed to the Substrate binary, the standard HTTP server and Web UI must be entirely disabled. The application should only listen and respond over Stdio (or SSE) using the MCP protocol.
