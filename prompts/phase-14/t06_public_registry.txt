CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
The Registry API lives in `api/internal/registry/`.
Consumer dependency fetching is in `api/internal/consumers/`.
Background jobs should reside in `workers/ingestion/`.

⚠️ CRITICAL CONTEXT: GLOBAL NAMESPACES ⚠️
The public registry introduces a global namespace mechanism (e.g., `@stripe/api`). This requires new `public_namespaces` and `public_schemas` tables that are distinctly separate from the internal, org-specific private registry schemas.
