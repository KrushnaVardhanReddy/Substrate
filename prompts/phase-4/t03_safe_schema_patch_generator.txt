TASK: P4-T03 — Safe Schema Patch Generator (Provider-Side Auto-Fix)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add a new `POST /api/v1/ai/autofix` endpoint to the Go API server
that receives a breaking change report and returns:
  1. A plain-English explanation of the impact.
  2. The exact safe schema patch the provider developer should apply
     (e.g., add @deprecated instead of deleting a field).

This endpoint is NOT streamed (unlike /ai/analyze). It returns a
single JSON response after calling the LLM synchronously. The LLM
provider uses the same three env vars as P4-T02:
  SUBSTRATE_AI_BASE_URL, SUBSTRATE_AI_API_KEY, SUBSTRATE_AI_MODEL

If SUBSTRATE_AI_BASE_URL is not set, return a deterministic mock
JSON response so CI and local dev without LM Studio still pass.

When this endpoint is triggered by a breaking change on a provider PR,
the GitHub Worker (github-app/) will call it and embed the returned
explanation + patch into the PR comment.

Spec (READ ONLY — implement from it, never edit):
  docs/specs/phase-4/ai-intelligence.md   (Section: P4-T03, P4-T04)

1. CREATE: api/internal/handlers/ai_autofix.go
──────────────────────────────────────────────────────────────

Package: handlers

Define the request/response structs:

  type BreakingChange struct {
      RuleID      string `json:"rule_id"`
      Path        string `json:"path"`
      Description string `json:"description"`
      Severity    string `json:"severity"`
  }

  type AIAutofixRequest struct {
      ProviderRepo          string           `json:"provider_repo"`
      SchemaType            string           `json:"schema_type"`   // "openapi" | "sql" | "graphql"
      CurrentSchema         string           `json:"current_schema"`
      ProposedSchema        string           `json:"proposed_schema"`
      BreakingChanges       []BreakingChange `json:"breaking_changes"`
  }

  type AIAutofixResponse struct {
      Explanation   string `json:"explanation"`    // 2-3 sentence plain-English summary
      SafePatch     string `json:"safe_patch"`     // The exact corrected schema snippet
      PatchLanguage string `json:"patch_language"` // "yaml" | "sql" | "graphql"
      MockMode      bool   `json:"mock_mode"`      // true if SUBSTRATE_AI_BASE_URL is not set
  }

Implement the handler:

  func AIAutofixHandler() http.HandlerFunc

The handler logic:

  Step 1: Only accept POST. Return 405 for other methods.

  Step 2: Parse JSON body into AIAutofixRequest. Return 400 on error.

  Step 3: Load AIConfig via loadAIConfig() (defined in ai_analyze.go,
    same package). If BaseURL is empty, return mockAutofixResponse().

  Step 4: Build the LLM system prompt (defined as a const):

    const autofixSystemPrompt = `You are Substrate AI, an API schema safety expert.
You will be given a provider's current and proposed schema, plus a list of breaking changes detected.
Your job is to:
1. Write a 2-3 sentence plain-English explanation of the impact on downstream consumers.
2. Generate the minimal safe schema patch the provider should apply instead.
   - For deleted fields: restore them with a @deprecated marker.
   - For removed endpoints: add a deprecation notice instead of removing.
   - For type changes: keep the old field and add a new one.
3. Return ONLY valid JSON matching this schema:
   {"explanation": "...", "safe_patch": "...", "patch_language": "yaml|sql|graphql"}
Do not include markdown fences or extra text outside the JSON.`

  Step 5: Build the user message:
    "Schema type: {schema_type}\nRepository: {provider_repo}\n\nCurrent schema:\n{current_schema}\n\nProposed schema:\n{proposed_schema}\n\nDetected breaking changes:\n{json_list_of_breaking_changes}"

  Step 6: Call the OpenAI-compatible chat completions endpoint
    (NON-streaming this time — "stream": false):
    POST {BaseURL}/chat/completions
    Header: Authorization: Bearer {APIKey}
    Body: {
      "model": "{Model}",
      "stream": false,
      "response_format": {"type": "json_object"},
      "messages": [
        {"role": "system", "content": autofixSystemPrompt},
        {"role": "user",   "content": userMessage}
      ]
    }

  Step 7: Parse the LLM response. The response is:
    {"choices": [{"message": {"content": "{\"explanation\":\"...\",\"safe_patch\":\"...\",\"patch_language\":\"yaml\"}"}}]}
    Extract `choices[0].message.content`, parse the inner JSON into
    AIAutofixResponse (without MockMode field, which defaults to false).

  Step 8: Set MockMode = false and write 200 JSON response.

  Step 9: On any error (network, JSON parse of LLM response), return
    500 with JSON: {"error": "AI autofix failed: <message>"}

Implement mockAutofixResponse:

  func mockAutofixResponse(w http.ResponseWriter) {
      w.Header().Set("Content-Type", "application/json")
      json.NewEncoder(w).Encode(AIAutofixResponse{
          Explanation:   "Mock mode: Removing 'user_id' from the response schema will break downstream consumers that read this field. Set SUBSTRATE_AI_BASE_URL to enable real AI analysis.",
          SafePatch:     "# Restore the field with a deprecation marker:\nuser_id:\n  type: string\n  deprecated: true\n  description: \"Deprecated — use account_id instead.\"",
          PatchLanguage: "yaml",
          MockMode:      true,
      })
  }
