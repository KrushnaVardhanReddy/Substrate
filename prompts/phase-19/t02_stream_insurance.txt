TASK: P19-T02 — Dynamic Schema Insurance for Ingested Streams

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Extend Substrate's Schema Insurance engine to validate incoming Airbyte data streams
at ingestion-time. When a record violates a declared stream contract (missing required
field, wrong type, null MRR), automatically generate an insurance_claims row so the
violation surfaces in the existing Insurance dashboard.

Spec (READ ONLY — implement from it, never edit):
  docs/specs/phase-19/p19-t02-schema-insurance-streams.md

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Validation MUST be asynchronous — it must NOT block the 202 Accepted ingest response.
  Use a goroutine dispatched after the DB insert, NOT a full River job queue.
- Do NOT re-implement the insurance claims schema. Reuse the existing insurance_claims
  table and ports.InsuranceStore exactly as defined in P15-T10.
- The core validation logic in stream_validator.go must be a pure function with no DB
  calls — DB interaction is only in the dispatch goroutine. This makes it unit-testable.
- A null or missing `mrr` field on a stream containing an `mrr` column is always HIGH severity.

═══════════════════════════════════════════════════════════════
IMPLEMENTATION TIPS
═══════════════════════════════════════════════════════════════
- StreamViolation struct: { Field string, Type string, Severity string, Detail string }
- ValidateRecord is a pure func: func ValidateRecord(contract StreamContract, record map[string]any) []StreamViolation
- The dispatch goroutine looks like:
    go func() {
      violations := ValidateRecord(contract, record)
      for _, v := range violations { insuranceStore.CreateClaim(ctx, ...) }
    }()
- Map violation severity to insurance claim: HIGH → "critical", MEDIUM → "warning", LOW → "info".
- For the GET violations endpoint, join insurance_claims WHERE claim_type = 'stream_violation'
  and parse the details JSON to filter by stream name.
