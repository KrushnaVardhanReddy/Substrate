TASK: P19-T01 — Airbyte Ingestion Adapter (sqlc)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Implement a Go backend adapter that accepts normalised Airbyte record streams via an
HTTP webhook endpoint and persists them to Substrate's Postgres staging tables using
sqlc-generated type-safe queries. This is the data-plane foundation for Universal
CRM Blast Radius — allowing any Airbyte connector (HubSpot, Snowflake, Chargebee, etc.)
to feed real MRR data into Substrate without a custom point integration.

Spec (READ ONLY — implement from it, never edit):
  docs/specs/phase-19/p19-t01-airbyte-adapter.md

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Do NOT import any Airbyte Go SDK. Implement the protocol natively (plain JSON over HTTP).
- All bulk record inserts MUST be wrapped in a single DB transaction — no partial ingestion.
- Connector configs MUST be encrypted at rest using the existing KMS BYOK key derivation
  from P15-T12. Reject POST /sources if no KMS key is derivable.
- Follow Hexagonal Architecture strictly: define an AirbyteStore port interface in
  api/internal/ports/airbyte.go; the sqlc adapter goes in api/internal/adapters/.
  HTTP handlers must only call port interfaces, never raw DB packages.
- Run `sqlc generate` after creating new SQL query files.

═══════════════════════════════════════════════════════════════
IMPLEMENTATION TIPS
═══════════════════════════════════════════════════════════════
- The two new DB tables are in the spec: airbyte_sources and airbyte_staged_records.
  Write the migration file first, then write airbyte.sql queries, then run sqlc generate.
- For config encryption: encrypt on write (POST /sources), decrypt on read only when
  needed for sync — never return raw config to the client.
- For bulk insert of records: use pgx's SendBatch or a single INSERT with unnest() for
  efficiency. The spec allows a simple loop inside a transaction for simplicity.
- The ingest endpoint is called by Airbyte acting as a destination — auth via
  Authorization: Bearer <INTERNAL_SERVICE_TOKEN> header.
