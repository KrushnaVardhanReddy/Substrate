═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Build a pure TypeScript module that converts DiffReport JSON into the
markdown string that Substrate posts as a GitHub PR comment.

This module is intentionally decoupled from the Worker infrastructure.
It can be developed, tested, and iterated independently of P2-T01 and P2-T02a.

The markdown templates MUST match docs/specs/github-app.md (Component 4) exactly.

═══════════════════════════════════════════════════════════════
CONTEXT — WHY THIS IS NEEDED
═══════════════════════════════════════════════════════════════
The PR comment is the primary user-facing output of Substrate. It must be:
  - Clear: devs should immediately understand what broke and where
  - Consistent: the format never changes unexpectedly between versions
  - Configurable: respects on_breaking_change: warn (advisory) vs block (failing)
  - Non-spammy: the Worker upserts the comment, never duplicating it

By isolating the formatting as a pure function, we get:
  - Easy unit testing (no mocking needed — pure input → output)
  - Easy iteration on the markdown format without touching Worker logic
  - Reusability in the API server (Phase 3) which also needs to render reports

2. FILE: github-app/src/formatter.ts
   Pure TypeScript module. NO imports from other github-app/ modules except types.ts.

   Export: formatPRComment(report: DiffReport, config: SubstrateConfig): string
   Three cases — implement EXACTLY as specified in docs/specs/github-app.md:

   Case 1: breaking_count > 0
   "## 🔴 Substrate — Breaking Changes Detected\n\nThis PR introduces **{N} breaking change(s)**..."
   - Table with ALL breaking changes (🔴 BREAKING rows) first, then warning rows (🟡 WARNING)
   - <details> block for info changes only (not for breaking/warning)
   - Attribution footer always present

   Case 2: breaking_count === 0, warning_count > 0
   "## 🟡 Substrate — Warnings Only\n\nNo breaking changes, but {N} warning(s) detected..."
   - Table with warning rows only

   Case 3: breaking_count === 0, warning_count === 0
   "## ✅ Substrate — All Clear\n\nNo breaking changes detected..."
   - No table

   Every case MUST end with:
   "\n---\n*Powered by [Substrate](https://github.com/KrushnaVardhanReddy/Substrate)*"

   Export: formatMissingConfigComment(): string
   Returns the setup prompt from docs/specs/github-app.md (Missing Config Behavior section).
   Must contain: "substrate init", "substrate.yaml", and the Substrate attribution footer.

   Export: getCommitStatusState(report: DiffReport, config: SubstrateConfig): 'success' | 'failure'
   - breaking_count === 0 → always 'success'
   - breaking_count > 0 AND on_breaking_change === 'warn' → 'success' (advisory mode)
   - breaking_count > 0 AND on_breaking_change === 'block' (or undefined) → 'failure' (default)

   Export: getCommitStatusDescription(report: DiffReport): string
   - breaking_count === 0 → "All clear — no breaking changes"
   - breaking_count > 0 → "{N} breaking change(s) detected"
