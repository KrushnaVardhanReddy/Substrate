TASK: P2-T02a — Add `substrate serve` HTTP Mode (Container Service)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Add a `serve` subcommand to the existing substrate CLI binary.

When run as `substrate serve --port 8080`, it starts an HTTP server that:
- Accepts POST /diff requests with JSON body containing raw spec file content
- Runs the existing diff engine logic (openapi or sql based on schema_type)
- Returns DiffReport JSON

This enables the Cloudflare Worker to call the diff engine over HTTP
without needing to embed the binary or use WebAssembly.

The implementation MUST follow docs/specs/github-app.md (Component 2) exactly.

═══════════════════════════════════════════════════════════════
CONTEXT — WHY THIS IS NEEDED
═══════════════════════════════════════════════════════════════
The Phase 1 CLI binary is invoked via `substrate diff <base> <head>` and reads from disk.
The Cloudflare Worker cannot shell out to a process — it needs to call the engine via HTTP.

The cleanest architecture (selected in the spec) is:
  Worker → HTTP POST /diff → Container Service → runs engine → returns DiffReport JSON

The Container Service IS the same Docker image we already publish (kpakkiragari/substrate-engine).
This task adds a new "serve" mode to that binary. CGO is already enabled (required for pg_query_go SQL parser).
The existing diff logic in engine/internal/ is NOT changed — only called via HTTP.

═══════════════════════════════════════════════════════════════
DELIVERABLES
═══════════════════════════════════════════════════════════════

1. FILE: engine/cmd/substrate/serve.go
   New file. Contains the HTTP server and the DiffRequest struct.

   DiffRequest struct:
     BaseSchema string `json:"base_schema"`   // required: raw spec file content
     HeadSchema string `json:"head_schema"`   // required: raw spec file content
     Config     string `json:"config"`        // optional: raw substrate.yaml content
     SchemaType string `json:"schema_type"`   // required: "openapi" | "sql"

   Routes:
     GET  /health → HTTP 200, body: {"status":"ok"}
     POST /diff   → run diff, return DiffReport JSON
     All other paths/methods → HTTP 404 or 405

   POST /diff logic:
   a. Decode JSON body → DiffRequest
   b. Validate required fields (base_schema, head_schema, schema_type present and non-empty)
   c. Write base_schema and head_schema to temp files (os.CreateTemp)
   d. Write config to temp file if non-empty
   e. defer os.Remove() all temp files before returning
   f. Call runOpenAPIDiff or runSQLDiff based on schema_type
   g. Return DiffReport as JSON with Content-Type: application/json

   Error responses (all as JSON):
     HTTP 400: {"error": "base_schema, head_schema, and schema_type are required"}
     HTTP 400: {"error": "unsupported schema_type: <value>"}
     HTTP 400: {"error": "invalid JSON"}
     HTTP 500: {"error": "internal diff error"}

   Function runOpenAPIDiff(basePath, headPath, configPath string) (*report.DiffReport, error):
     - Call the existing CompareOpenAPI function from engine/internal/diff/openapi.go
     - Apply overrides from configPath if non-empty (call existing config parsing logic)
     - Return the DiffReport

   Function runSQLDiff(basePath, headPath, configPath string) (*report.DiffReport, error):
     - Call the existing CompareSQL function from engine/internal/diff/ (or equivalent)
     - Apply overrides from configPath if non-empty
     - Return the DiffReport

   Function runServe(port string) error:
     - Create http.NewServeMux() and register /health and /diff handlers
     - Listen on 0.0.0.0:{port} using http.ListenAndServe
     - Log startup message: "substrate serve: listening on :{port}"

2. FILE: engine/cmd/substrate/main.go  (MODIFY — add serve case only)
   Add to the existing subcommand switch:
     case "serve":
       port := "8080"
       // parse --port flag from os.Args
       if err := runServe(port); err != nil {
           log.Fatal(err)
       }
   Do NOT change any other cases or existing logic.
