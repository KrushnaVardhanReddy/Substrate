TASK: P9-T12 — Embedded SQLite (LibSQL) Local Caching

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Embed SQLite into the CLI and MCP Server to pull background graph updates, enabling sub-millisecond, zero-latency local schema diffs without hitting the cloud API.

Spec (READ ONLY — implement from it, never edit):
  docs/specs/phase-9/p9-t12-embedded-sqlite.md

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Use ONLY `github.com/tursodatabase/libsql-client-go` or `github.com/mattn/go-sqlite3`. Since we may want to sync with Turso later, prefer LibSQL, but `mattn/go-sqlite3` is acceptable if CGO issues arise in WASM builds. For this task, use `github.com/mattn/go-sqlite3` strictly since we need WASM compatibility down the line. 
- Do NOT alter the central Postgres database in `api/`. This is ONLY for `engine/cmd/substrate`.
- Ensure migrations for the local SQLite db run automatically on CLI start.

═══════════════════════════════════════════════════════════════
CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
The CLI lives in `engine/cmd/substrate/main.go`.
The MCP server lives in `engine/cmd/substrate-mcp/main.go`.

⚠️ CRITICAL CONTEXT: CONCURRENCY IN SQLITE ⚠️
SQLite is highly susceptible to `database is locked` errors if written to concurrently. Ensure you enable WAL mode (`PRAGMA journal_mode=WAL;`) upon connection, and only use a single writer connection for the background sync process.
