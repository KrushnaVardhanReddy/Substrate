━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Create a new directory: `engine/cmd/substrate/testdata/cross-repo/`

Inside it, create exactly three fixture files to simulate a multi-repository scenario. You MUST use these exact contents so the test is deterministic.

**1. `provider_base.yaml` (The backend API's original OpenAPI spec)**
```yaml
openapi: 3.0.0
info:
  title: Provider API
  version: 1.0.0
paths:
  /users:
    get:
      responses:
        '200':
          description: OK
```

**2. `provider_head.yaml` (The backend API's PR, introducing a breaking change)**
```yaml
openapi: 3.0.0
info:
  title: Provider API
  version: 1.0.0
paths:
  /admin: # Changed from /users to /admin, deleting the /users path!
    get:
      responses:
        '200':
          description: OK
```

**3. `consumer_snapshot.yaml` (The frontend's required snapshot, exactly matching base)**
```yaml
openapi: 3.0.0
info:
  title: Provider API
  version: 1.0.0
paths:
  /users:
    get:
      responses:
        '200':
          description: OK
```

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
2. Implement E2E Test (`engine/cmd/substrate/e2e_test.go`)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Add a new dedicated test function: `TestCrossRepoCheckE2E(t *testing.T)`

You must simulate the orchestration layer. In production, the Worker runs the CLI comparing the `head` of the PR against the `snapshot` of the consumer.

Execute the compiled CLI binary (using `exec.Command` like the other tests in this file) with the following arguments:
`diff --base testdata/cross-repo/consumer_snapshot.yaml --head testdata/cross-repo/provider_head.yaml --type openapi --format json`

**Assertions MUST check:**
1. The process exit code MUST be `1` (indicating a breaking change).
2. Read stdout into a `report.DiffReport` struct.
3. Assert that `Summary.BreakingCount == 1`.
4. Assert that `Breaking[0].Rule == "ENDPOINT_REMOVED"`.
5. Assert that `Breaking[0].Path == "GET /users"`.

This guarantees that the core diff engine accurately catches cross-repo breaking changes using the snapshot methodology.
