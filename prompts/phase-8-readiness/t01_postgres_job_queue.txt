TASK: P8-T01 — PostgreSQL Job Queue (River)

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Offload synchronous webhook processing and AI diff generation to a Postgres-backed background job queue (`riverqueue/river`). This prevents GitHub App webhook timeouts for large repos and avoids introducing external infrastructure dependencies like Redis.

Spec (READ ONLY — implement from it, never edit):
  docs/specs/phase-8/p8-t01-postgres-job-queue.md

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Do NOT use Redis, RabbitMQ, or any other external message broker.
- Only use `github.com/riverqueue/river` and `github.com/riverqueue/river/riverdriver/riverpgxv5`.
- Ensure migrations cleanly create the riverqueue tables.

═══════════════════════════════════════════════════════════════
CONTEXT — EXISTING REPO LAYOUT & ARCHITECTURE
═══════════════════════════════════════════════════════════════
The Registry API lives in `api/`.
Handlers are in `api/internal/handlers/` and `api/internal/webhook/`.
Server initialization is in `api/internal/server/`.

⚠️ CRITICAL CONTEXT: CYCLIC IMPORT DANGER ⚠️
In previous attempts, a cyclic import occurred because `handlers` imported `workers` (to enqueue jobs), and `workers` imported `handlers` (to execute the actual business logic like `PerformCrossRepoCheck` or `GenerateAutofixPatch`).
To solve this, you MUST extract the core business logic from `handlers` and `webhook` into a newly created `api/internal/services` package.
- `services` executes the logic. It imports ONLY models, db, and types.
- `workers` imports `services` to execute jobs.
- `handlers` imports `workers` to enqueue jobs, OR imports `services` for synchronous tasks.
Never let `workers` import `handlers`.
