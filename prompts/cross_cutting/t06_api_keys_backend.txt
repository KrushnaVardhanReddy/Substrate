OBJECTIVE
═══════════════════════════════════════════════════════════════
Implement the full backend database schema, Go API endpoints, and SvelteKit integration for Organization-scoped API Keys to replace the current placeholder UI.

Spec (READ ONLY — implement from it, never edit):

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- The raw API key must NEVER be stored in the database. You must generate a secure token (using PASETO v4.local or standard secure random strings), hash it via Bcrypt/Argon2, and store only the hash + prefix in the `api_keys` table.
- The raw key must be returned EXACTLY ONCE to the frontend upon generation.
- Ensure standard backend tests are added (e.g. `api_keys_test.go`) validating creation, listing, and revocation.
- Ensure the SvelteKit frontend is hooked up to the real `/api/v1/org/{org}/apikeys` endpoints.
