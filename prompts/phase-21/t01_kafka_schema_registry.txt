TASK: P21-T01 — Kafka / Confluent Schema Registry Live Webhook Receiver

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Implement a webhook receiver that accepts schema change events from Confluent Schema
Registry and Apicurio Registry (CloudEvents format). On receipt, persist the new schema
version, diff it against the previous version using the existing Avro/Protobuf diff
engine, and create a breaking change event if violations are found.

This opens event-driven teams (Kafka-first) as a new market segment — no competitor
governs Kafka schema evolution today outside the Schema Registry itself.

Spec (READ ONLY — implement from it, never edit):
  docs/specs/phase-21/p21-t01-kafka-schema-registry.md

═══════════════════════════════════════════════════════════════
CONSTRAINTS & RULES
═══════════════════════════════════════════════════════════════
- Do NOT connect to Kafka brokers. Webhook-only architecture.
- Support BOTH Confluent Schema Registry payload AND Apicurio CloudEvents payload formats.
- Breaking change detection MUST reuse the existing diff engine adapters in api/internal/diff/.
  Do NOT duplicate diff logic.
- Token auth: SHA-256 hash only — same pattern as otel_sources.token_hash (P20-T01).
- Breaking change events use the existing `events` table (same as P17-T06 deployment events)
  with type = "kafka_breaking_change". Do NOT create a new events table.
- Hexagonal: KafkaSchemaStore port in api/internal/ports/kafka.go.

═══════════════════════════════════════════════════════════════
CONTEXT — EXISTING REPO LAYOUT
═══════════════════════════════════════════════════════════════

═══════════════════════════════════════════════════════════════
IMPLEMENTATION TIPS
═══════════════════════════════════════════════════════════════
- Payload detection: check for `specversion` field → CloudEvents (Apicurio).
  Otherwise treat as Confluent format.
- Previous version lookup: SELECT schema_raw FROM kafka_schema_versions WHERE
  org=$1 AND subject=$2 AND version=$3 ORDER BY version DESC LIMIT 1.
- Diff invocation: schemaType = "AVRO" → call diff.DiffAvro(prev, new).
  schemaType = "PROTOBUF" → call diff.DiffProtobuf(prev, new).
  schemaType = "JSON" → call diff.DiffJSONSchema(prev, new) if it exists, else skip diff.
- If no previous version exists (first ingestion), store but skip diff — not a breaking change.
