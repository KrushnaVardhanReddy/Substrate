═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
P1b-T02 shipped the core SQL diff engine (parser + diff + rule engine).
P1b-T03 expands it with the remaining rules from the spec that were not
fully covered, hardens the edge-case test suite, and ensures the engine
handles realistic pg_dump output without false positives.

This task does NOT redesign the engine. It adds to the existing code in
engine/internal/sql/diff.go and engine/internal/sql/diff_test.go.

Specifically, you must:

1. VERIFY the following rules from the spec are correctly implemented
   in diff.go. If any are missing or incorrect, fix them:
     a. TABLE_RENAMED   — Levenshtein similarity > 0.7 AND same column set
     b. COLUMN_RENAMED  — Levenshtein similarity > 0.7 AND same DataType
     c. SQL_ENUM_TYPE_REMOVED  — entire ENUM type dropped from schema
     d. VIEW_DEFINITION_CHANGED — view exists in both but its Definition
        string changed (currently only VIEW_COLUMN_REMOVED is diffed)

2. ADD the missing VIEW_DEFINITION_CHANGED rule logic to diffViews():
     Rule ID:  VIEW_DEFINITION_CHANGED
     Severity: WARNING
     Pattern:  View exists in both base and head, its column list is
               unchanged, but its Definition (SQL query) differs.
     Rationale: The view still exposes the same columns, but the
                underlying data may differ — a silent semantic change.

3. ADD tests in diff_test.go for the four rules above using fixture
   file pairs in testdata/.

4. ADD edge-case tests covering realistic pg_dump output patterns:
     a. Multi-statement ALTER TABLE in one file (add + drop column)
        in the same ALTER TABLE statement block.
     b. Schema with pg_dump headers (SET, COMMENT ON TABLE, GRANT,
        SELECT pg_catalog.setval) — parser must skip them without error.
     c. NUMERIC precision widening: NUMERIC(10,2) → NUMERIC(18,2)
        → should be COLUMN_TYPE_WIDENED (WARNING), not COLUMN_TYPE_CHANGED.
     d. varchar without length (TEXT-like): VARCHAR → VARCHAR with no
        length → should be NO_CHANGE (same type, no length specified).
     e. Column with DEFAULT added to existing NOT NULL column
        → COLUMN_DEFAULT_CHANGED (WARNING), not BREAKING.

5. ADD E2E tests in e2e_sql_test.go for at least two of the new cases:
     - TABLE_RENAMED detected (exit code 2, output contains "TABLE_RENAMED")
     - View definition changed (exit code 1, output contains "VIEW_DEFINITION_CHANGED")
