TASK: P1b-T02 — SQL DDL Parser + Diff Engine + Rule Engine

═══════════════════════════════════════════════════════════════
OBJECTIVE
═══════════════════════════════════════════════════════════════
Build a complete PostgreSQL schema diff engine in a new package
`engine/internal/sql/`. It must:

1. Parse two PostgreSQL DDL snapshot files (schema.sql) into an
   internal representation (IR) Go struct tree.
2. Diff the two IR trees to produce a raw list of changes.
3. Apply the 26 breaking-change rules from the spec to classify
   each change into BREAKING / WARNING / SAFE.
4. Return a standard `*report.DiffReport` — the same struct used
   by the OpenAPI engine.
5. Wire the new engine into the CLI so `substrate diff base.sql
   head.sql` (or schema_type: sql in substrate.yaml) uses it.

The spec is at docs/specs/breaking-change-rules-sql.md.
Implement it exactly as written.

═══════════════════════════════════════════════════════════════
CONTEXT — WHY THIS IS NEEDED
═══════════════════════════════════════════════════════════════
Substrate currently only diffs OpenAPI specs. Teams using
PostgreSQL routinely break downstream services by:
  - Dropping or renaming columns that ORMs reference
  - Adding NOT NULL columns without a DEFAULT (old INSERTs fail)
  - Adding UNIQUE constraints that invalidate existing data

The SQL engine catches these in CI before they reach production.

Input: Two plain .sql files — output of `pg_dump --schema-only`.
Output: Standard *report.DiffReport (same JSON schema as OpenAPI).
No changes to the DiffReport struct are needed.

FILE 1: engine/internal/sql/schema.go
──────────────────────────────────────────────────
Defines the Internal Representation (IR) structs.
Implement EXACTLY these types (no additions, no removals):

  type SQLSchema struct {
      Tables    map[string]*Table
      Views     map[string]*View
      Enums     map[string]*EnumType
      Sequences map[string]*Sequence
  }

  type Table struct {
      Name        string
      Columns     map[string]*Column
      Constraints map[string]*Constraint
      Indexes     map[string]*Index
  }

  type Column struct {
      Name         string
      DataType     string   // normalized lowercase: "varchar","integer","bigint","text","boolean","timestamp","numeric","date","uuid","jsonb","bytea"
      Length       *int     // VARCHAR(n) -> n; nil otherwise
      Precision    *int     // NUMERIC(p,s) -> p
      Scale        *int     // NUMERIC(p,s) -> s
      NotNull      bool
      Default      *string  // nil = no default
      IsPrimaryKey bool
  }

  type Constraint struct {
      Name       string
      Type       string    // "PRIMARY_KEY","UNIQUE","CHECK","FOREIGN_KEY"
      Columns    []string
      CheckExpr  *string
      RefTable   *string
      RefColumns []string
  }

  type Index struct {
      Name    string
      Columns []string
      Unique  bool
      Where   *string
  }

  type View struct {
      Name         string
      Definition   string
      Columns      []string
      Materialized bool
  }

  type EnumType struct {
      Name   string
      Values []string
  }

  type Sequence struct {
      Name      string
      DataType  string
      Start     int64
      Increment int64
  }

Data type normalization rules (apply in parser, store normalized):
  INT / INT4 / INTEGER            → "integer"
  INT2 / SMALLINT                 → "smallint"
  INT8 / BIGINT                   → "bigint"
  BOOL / BOOLEAN                  → "boolean"
  FLOAT4 / REAL                   → "real"
  FLOAT8 / DOUBLE PRECISION       → "double precision"
  CHARACTER VARYING(n) / VARCHAR  → "varchar"
  CHARACTER(n) / CHAR             → "char"
  TIMESTAMP WITH TIME ZONE        → "timestamptz"
  TIMESTAMP / TIMESTAMP WITHOUT TZ→ "timestamp"
  All others                      → lowercase as-is

FILE 2: engine/internal/sql/parser.go
──────────────────────────────────────────────────
Parses a PostgreSQL DDL .sql file (from pg_dump --schema-only)
into a *SQLSchema IR.

Public API:
  func ParseSchema(path string) (*SQLSchema, error)
  func ParseSchemaFromBytes(src []byte) (*SQLSchema, error)

Implementation:
  - Use "github.com/pganalyze/pg_query_go/v6" to parse DDL.
  - Add it to engine/go.mod: `go get github.com/pganalyze/pg_query_go/v6`
  - Iterate over the parse tree's Stmts slice.
  - Handle these statement types:
      CreateStmt          → Table
      AlterTableStmt      → modify existing Table (columns, constraints)
      IndexStmt           → Index on Table
      ViewStmt            → View
      CreateTableAsStmt   → View (materialized if indicated)
      CompositeTypeStmt   → EnumType (only ENUM variants)
      CreateSeqStmt       → Sequence
  - Return error (with message "sql parse error: <detail>") if
    the input is not valid PostgreSQL DDL.
  - Silently skip statement types not listed above (e.g., INSERT,
    COMMENT, GRANT, SET, SELECT) — pg_dump output contains them.

Column type normalization MUST happen at parse time, not diff time.

FILE 3: engine/internal/sql/diff.go
──────────────────────────────────────────────────
Diffs two *SQLSchema IRs and returns a classified *report.DiffReport.

Public API:
  func DiffSchemas(base, head *SQLSchema) *report.DiffReport

Implementation steps:

STEP 1 — Tables
  For each table in base:
    If absent in head → TABLE_REMOVED (BREAKING)
    Else → diff columns, constraints, indexes (see below)
  For each table in head not in base:
    Check TABLE_RENAMED heuristic (see below)
    If no rename match → TABLE_ADDED (SAFE)

STEP 2 — Columns (per table present in both)
  For each column in base table:
    If absent in head table:
      Check COLUMN_RENAMED heuristic (see below)
      If no rename match → COLUMN_REMOVED (BREAKING)
    Else diff the column:
      DataType changed:
        If widening pair (see spec) → COLUMN_TYPE_WIDENED (WARNING)
        Else → COLUMN_TYPE_CHANGED (BREAKING)
      NotNull: false→true → COLUMN_MADE_NOT_NULL (BREAKING)
      NotNull: true→false → COLUMN_NULLABLE_CHANGED (SAFE)
      Default removed (was non-nil, now nil) AND NotNull:
        → COLUMN_DEFAULT_REMOVED (BREAKING)
      Default removed AND NOT NotNull:
        → COLUMN_DEFAULT_CHANGED (WARNING)
      Default changed (was non-nil, now different non-nil):
        → COLUMN_DEFAULT_CHANGED (WARNING)
  For each column in head table not in base:
    If NotNull == true AND Default == nil:
      → COLUMN_ADDED_NOT_NULL_NO_DEFAULT (BREAKING)
    Else:
      → COLUMN_ADDED_NULLABLE (SAFE)

STEP 3 — Constraints (per table present in both)
  For each constraint in base not in head (by name):
    Type PRIMARY_KEY → PRIMARY_KEY_CHANGED (BREAKING)
    Type UNIQUE      → CONSTRAINT_REMOVED (WARNING)
    Type CHECK       → CONSTRAINT_REMOVED (WARNING)
    Type FOREIGN_KEY → CONSTRAINT_REMOVED (WARNING) [named CONSTRAINT_REMOVED_FK internally, reported as CONSTRAINT_REMOVED]
  For each constraint in head not in base (by name):
    Type PRIMARY_KEY → PRIMARY_KEY_CHANGED (BREAKING)
    Type UNIQUE      → CONSTRAINT_ADDED_UNIQUE (BREAKING)
    Type CHECK       → CONSTRAINT_ADDED_CHECK (BREAKING)
    Type FOREIGN_KEY → FOREIGN_KEY_ADDED (BREAKING)

STEP 4 — Indexes (per table present in both)
  In base not in head → INDEX_REMOVED (WARNING)
  In head not in base → INDEX_ADDED (SAFE)

STEP 5 — Views
  In base not in head → VIEW_REMOVED (BREAKING)
  In head not in base → VIEW_ADDED (SAFE)
  In both: if Columns differ → VIEW_COLUMN_REMOVED (BREAKING) for
    each column in base not in head

STEP 6 — Enums
  In base not in head → SQL_ENUM_TYPE_REMOVED (BREAKING)
  In both:
    Values in base not in head → SQL_ENUM_VALUE_REMOVED (BREAKING)
    Values in head not in base → SQL_ENUM_VALUE_ADDED (WARNING)

RENAME HEURISTIC (for TABLE_RENAMED and COLUMN_RENAMED):
  Use normalized Levenshtein distance similarity score.
  score = 1 - (levenshtein(a,b) / max(len(a),len(b)))
  If score > 0.7 AND the column set is identical (for tables) or
  the DataType matches (for columns) → treat as RENAME (BREAKING).
  Implement levenshtein in a private helper function.
  Do NOT import external libraries for this.

WIDENING TYPE PAIRS (COLUMN_TYPE_WIDENED, not COLUMN_TYPE_CHANGED):
  smallint  → integer
  smallint  → bigint
  integer   → bigint
  real      → double precision
  varchar(n)→ varchar(m) where m > n (compare Length fields)
  numeric(p,s)→ numeric(p2,s) where p2 > p (compare Precision)
All other type changes → COLUMN_TYPE_CHANGED (BREAKING).

REPORT ASSEMBLY:
  Use the same pattern as engine/internal/diff/openapi.go:
    rep := &report.DiffReport{
        SubstrateVersion: "0.1.0",
        SchemaType:       report.SchemaTypeSQL,
        ComparedAt:       time.Now().UTC().Format(time.RFC3339),
        BreakingChanges:  []report.Change{},
        Warnings:         []report.Change{},
        SafeChanges:      []report.Change{},
    }
  Change.ID format:   "chg_<ruleid_lower>_<table>_<column>"
  Change.RuleID:      the rule ID string from the spec
  Change.Severity:    report.ChangeSeverityBreaking / Warning / Safe
  Change.Path:        "tables.<tablename>" or "tables.<tablename>.columns.<colname>"
  Change.Description: human-readable explanation (see examples below)

Description examples:
  TABLE_REMOVED:                 "Table 'orders' was removed."
  COLUMN_REMOVED:                "Column 'email' was removed from table 'users'."
  COLUMN_ADDED_NOT_NULL_NO_DEFAULT: "Column 'customer_id' added as NOT NULL without a DEFAULT — existing INSERTs will fail."
  COLUMN_TYPE_CHANGED:           "Column 'age' type changed from 'varchar' to 'integer'."
  COLUMN_MADE_NOT_NULL:          "Column 'phone' changed from nullable to NOT NULL — existing NULLs will be rejected."
  CONSTRAINT_ADDED_UNIQUE:       "UNIQUE constraint 'users_email_key' added to table 'users'."
  FOREIGN_KEY_ADDED:             "FOREIGN KEY 'fk_orders_user' added to table 'orders'."
  VIEW_REMOVED:                  "View 'customer_summary' was removed."
  SQL_ENUM_VALUE_REMOVED:        "Enum value 'CANCELLED' removed from type 'order_status'."
