# Phase 20 — Task 99: E2E Validation (No Mocks)

## 1. Overview

Validate the full OTel ingestion pipeline end-to-end against real PGlite: token
provisioning, OTLP metric ingestion (JSON format), traffic-enriched blast radius,
and MCP tool parity.

## 2. Test Scenarios

### Scenario 1: OTel Source Lifecycle
1. `POST /api/v1/org/test-org/otel/sources` → assert `201` + token returned.
2. `GET /api/v1/org/test-org/otel/sources` → assert source appears.
3. `DELETE /api/v1/org/test-org/otel/sources` → assert `204`.
4. Retry `GET` → assert empty list.

### Scenario 2: OTLP JSON Metric Ingestion
1. Provision a token for `test-org`.
2. `POST /api/v1/otel/v1/metrics` with OTLP JSON payload containing:
   - `service.name: checkout-service`
   - `http.route: GET /api/v1/payments`
   - `http.method: GET`
   - `req_count: 1500` over a 1-minute window.
3. Assert `202 Accepted`.
4. `GET /api/v1/org/test-org/otel/traffic` → assert route row exists with `req_count >= 1500`.

### Scenario 3: Traffic-Enriched Blast Radius
1. Seed traffic for `checkout-service → GET /api/v1/payments` with `req_count: 5000`.
2. `GET /api/v1/impact/test-org/payments-api` → assert consumer `checkout-service`
   has `traffic_weight.req_per_min > 0` and `risk: CRITICAL`.

### Scenario 4: MCP Tool Parity
1. Open MCP session. Call `get_route_traffic` for `test-org / GET /api/v1/payments`.
2. Assert response contains `req_per_min`, `p99_ms`, `error_rate_pct`.
3. Call `get_top_traffic_routes` for `test-org` → assert `GET /api/v1/payments` is first.
4. Call `get_traffic_enriched_blast_radius` → assert `checkout-service` appears with
   `traffic_weight` populated.

### Scenario 5: Auth Rejection
1. `POST /api/v1/otel/v1/metrics` with no `Authorization` header → assert `401`.
2. `POST /api/v1/otel/v1/metrics` with invalid token → assert `401`.

## 3. Rules

- No mocks — all assertions against real DB rows.
- Mirror test structure from `scripts/e2e/phase19_e2e_test.go` exactly.
- Use OTLP JSON (not protobuf) for E2E tests to avoid test binary bloat.
- Use `require.NoError` for infrastructure setup steps.
- Each scenario cleans up seeded `otel_sources` + `otel_route_traffic` via `t.Cleanup`.
