# Phase 18 - Task 99: E2E Validation (No Mocks)

## 1. Objective
Validate all Phase 18 AI Agent Governance features end-to-end using real Go API tests.

## 2. Database Seed
```sql
INSERT INTO agent_profiles (org, name, allowed_tools, hitl_enabled)
  VALUES ('ai-org', 'support-agent', ARRAY['get_schema', 'get_blast_radius'], true);
```

## 3. Go API Tests (`scripts/e2e/phase18_e2e_test.go`)
- `POST /api/v1/mcp/profiles` — assert creates a profile and returns 201 with an `id`.
- `GET /api/v1/mcp/profiles/ai-org` — assert returns the seeded profile.
- Start an MCP session with `?profile_id=<id>` — assert `tools/list` only returns `get_schema` and `get_blast_radius`, not destructive tools like `delete_rule`.
- Call a HITL-gated tool (`POST`-type) — assert response has `status: pending_approval` and a new row appears in `hitl_queue`.
- `GET /api/v1/mcp/hitl-queue/ai-org` — assert returns the pending item.
- `POST /api/v1/schema/prune` with `{ org: "ai-org", repo: "payments-api", intent: "check billing status" }` — assert returns a pruned OpenAPI object containing only billing-related endpoints, and not auth or user management endpoints.
- Call the prune endpoint again with the same intent — assert response is served from cache (same `computed_at`).

## 4. Constraints
- The schema pruning test MUST use the real AI embedding handler — do NOT mock the similarity computation.
- HITL queue tests must assert the actual database row state, not just HTTP response codes.
